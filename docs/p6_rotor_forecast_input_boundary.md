# P6 预测风况至转子载荷的输入边界

更新日期：2026年8月23日
状态：冻结输入约束，不将预测风况接入控制器或批量验证。

## 已具备的基础

公开 IEA 15 MW 输入包中的 `Cp_Ct_Cq.IEA15MW.txt` 提供二维
\(C_T(\beta,\lambda)\) 表。运行库现用
`RotorPerformanceOperatingPoint` 显式保存一次查询所需的桨距、转速、转子半径和法向入流速度，并由
`RotorPerformanceTable.ct_at_operating_point` 在表内插值得到 \(C_T\)。

该对象只用于建立尖速比 \(\lambda=\Omega R/U_n\)。它不选择桨距或转速，也不把测风高度的风速解释为转子平面入流。表外桨距或尖速比继续直接拒绝。

性能表查询本身不把 \(C_T\) 限制为正值。进入准定常正推力关系时，负 \(C_T\) 仍由载荷模块拒绝，因此“表内可查”和“可用于正推力载荷”是两个不同条件。

## 不能省略的物理输入

当前 FINO1 数据准备脚本记录的风速高度为 102 m，而参考平台轮毂高度为 150 m；风向的实际观测高度还可能为 91 m 或 82 m。因此，预测得到的 ENU 风矢量不能直接作为转子平面风速。接入前必须明确：

1. 测风高度到转子平面的风速和风向处理；
2. 每个预测点采用的桨距、转速或等价运行点规则；
3. 冻结平台艏向、当前相对平台机舱偏航、零偏航参考转子几何，以及非零偏航时的偏航轴位置；
4. 未来点的参考点速度与角速度怎样给定；
5. 预测点怎样保持或插值为平台子步载荷。

现有 `quasi_steady_rotor_generalized_load_from_enu_wind` 只在以上输入已经明确时进行坐标组合、相对风计算及广义载荷映射。它不完成高度换算、运行点选择、偏航控制、诱导动态、局部轮毂气动力矩或预测点到子步的调度。

## 当前停止位置

本阶段可用的结果仅为：给定一个明确转子运行点和已经定义的转子平面入流，系统可以从公开 \(C_T\) 表生成有来源的准定常转子广义载荷。它不能说明 FINO1 预测已生成真实气动载荷，也不能用于候选动作评分、目标水量更新或控制性能结论。

## P6.1 显式预测载荷组装接口

`wind_prediction.forecast_physical_load`现将一份`ForecastEvidence`与调用方给定的
物理输入组装为`GeneralizedLoadForecast`。输入明确包括空气密度、转子半径、冻结
平台艏向、零偏航参考转子几何，以及当前和每个预测点的`C_T`、平台平动速度和角速度。
每次组装结果同时保留本次参数和运行状态对象，因此不会把这些假设只留在说明文字中。

测风高度到转子平面的处理也不使用默认值。调用方必须提供风矢量的有效参考高度、
转子平面高度和幂律指数。接口仅按这个显式的标量速度因子换算二维ENU下风向
矢量，保留原方向，并明确不描述风向随高度变化、垂向风或湍流廓线变化。这是可替换的
低阶研究假设，不是FINO1测量已经等同于轮毂来流的主张。

输出仍是离散载荷点：当前载荷单独使用调用方提供的原点时刻风矢量，第一份未来
载荷严格对应`+sample_period_s`。事件概率和预测可靠度不缩放物理载荷，预测点
之间也不在这里插值、保持或施加到平台子步。该接口只为后续单时距状态与RHS端点诊断
提供输入，尚未接入候选评分、目标水量更新或性能比较。

当前观测风的时间与预测原点在两者均提供时必须严格一致，接口不承担时延补偿、插值
或时间对齐。每个预测点的`C_T`、平台平动速度和角速度在组装时复制为只读值，以防
调用方后续修改数组而改变已记录的物理载荷身份。

未来平台运动不再只由数组形状表示。`ForecastRotorOperatingState`要求调用方同时给出
未来运动学模式及其来源标签：`frozen_zero`只允许每个预测提前量的平动和角速度均为零，
表示冻结平台运动的低阶近似；`explicit_per_lead`表示调用方为每个离散预测点提供了对应的
平动和角速度。两种模式及其来源都会复制进`ForecastPhysicalInputIdentity`。该标记并不预测
平台运动，也不判断哪种近似更准确，只避免将零数组或外部轨迹的物理含义隐含在调用方代码中。

`ForecastGeneralizedLoadAssembly`会再次核对该身份记录与实际运行状态中的运动学模式、来源标签和预测长度完全一致。因而手工拼接的载荷组装结果不能以`frozen_zero`标签掩盖另一条未来平台运动假设。

转子朝向同样不再由固定法向隐含。平台艏向只负责将ENU风矢量转换到冻结平台坐标，
不等同于机舱偏航。零偏航参考法向和轮毂作用点由原点时刻外部给定的相对平台机舱偏航角
共同确定，其中轮毂只绕显式的偏航轴位置旋转其相对偏置，避免将固定塔架几何误作可旋转
力臂。当前只支持`frozen_current`，即整个预测域复用原点时刻的外部朝向。接口不根据当前风
或未来风自动设置艏向或偏航，也不实现偏航控制器。

正推力关系仍只适用于相对风沿声明的下风转子法向具有非负投影的记录。背向投影会被
明确拒绝，不能通过绝对值、法向翻转或把`C_T`静默设为零来伪造正推力。停机、顺桨、
背风气动和动态偏航均仍在当前低阶载荷链外。

同一组装对象中的当前和各未来六分量载荷也必须分别与`RotorGeneralizedLoad`记录相同，预测提前量固定为样本周期的整数倍。这样，未来平台轨迹、端点诊断和水泵预演不会在同一预测编号下读取不同的载荷或时间网格。

## P6.2 预测输入的持久性对照核验

在同一当前平台状态、水泵状态、转子性能表、名义运行设定和物理参数下，可将未来风矢量替换为当前观测风的重复序列，形成仅改变未来风况输入的持久性对照。两条路径均按各自的未来法向相对来流重算每个预测点的名义运行点和\(C_T\)，不复用另一条路径的系数。该检查不比较任何控制性能，也不选择目标。它只核对实际预测与持久性对照之间的未来广义载荷、冻结轨迹、同一时刻RHS端点和`new_track`目标会随未来风矢量而变化，`continue_existing`和`release_to_current`则继续只由共同的进入时刻泵状态决定。

该对照只在`scripts/validation/run_real_lstm_physical_cycle_smoke.py --include-persistence-contrast`中显式构造，不进入`forecast_evidence.py`或控制器。对照记录以`validation_current_observation_persistence`和`current_observation_repeat_not_model`标识来源，事件概率为空、可靠度为零。`provides_future_preview=True`在这里仅表示每个未来提前量都存在显式风矢量，不能解释为模型预测、预测精度或线上控制许可。

可靠度和事件概率的变化不能替代这一对照。两者在当前阶段不得改变物理载荷、RHS端点、三舱目标或水泵预演。只有这一输入边界稳定后，才可在独立的决策层讨论可靠度和事件信息是否应限制某类目标操作。

## P6.3 单周期物理事实组装入口

`assemble_first_interval_physical_cycle_input()`是现有物理影子链的唯一单周期组装入口。它接收一份已经由重放预测源生成的`ForecastEvidence`、调用方标识且与预测原点时间绑定的当前ENU风、显式转子物理参数和运行状态、冻结平台快照与初态、当前及预测区间的显式非转子载荷、水泵状态及执行配置，并按固定顺序组装：

```text
ForecastEvidence
  -> 来源绑定的预测转子载荷
  -> 冻结舱水量的预测轨迹
  -> 首预测点RHS及三舱端点
  -> new_track / continue_existing / release_to_current
  -> FirstIntervalPhysicalDecisionInput
```

该入口不新增结果类型，只返回已有的`FirstIntervalPhysicalDecisionInput`。预测原点必须存在，且当前风记录、平台初态和水泵状态各自携带的时间标签都必须与之严格一致。非转子区间载荷也必须给出同一预测原点和提前量网格，未绑定的环境载荷不能进入该入口。首个预测提前量唯一决定端点和预演时长，不开放任意提前量、端点比例或控制评分。当前转子载荷所用的平台平动和角速度还必须与同一初始平台状态一致，实际舱水量和共享舱容也必须与平台快照逐项一致。

当前观测风形成原点时刻的`current_rotor_load`，并与调用方显式给出的当前波浪、其他载荷和当前舱水量共同形成原点完整RHS。该原点RHS只记录同一时刻的状态方程，不生成压载需求或目标。冻结预测轨迹仍按右端预测点反向保持的约定，仅由未来离散载荷推进，因此不会将原点载荷插值或混入首个预测区间。相应地，单周期物理事实仅使用第一个预测点形成首区间RHS和水泵预演，后续预测点仍保留在轨迹中，但不会改变这一首区间响应。这是当前影子链的明确作用范围，不是连续气动力或多周期闭环预测的近似结论。

这只建立“真实预测记录能够进入物理事实链”的可追溯入口，并不将其接入旧控制器，不从事件概率或可靠度推导物理载荷，也不选择三种生命周期操作。后续若要形成新的决策规则，仍须另行冻结安全口径、互斥条件和评价时标。

## P6.4 重放样本的当前观测绑定

`ReplayForecastEvidenceSource.source_bound_forecast_and_current_observation()`从同一个
`ReplaySample`返回模型预测和该样本历史末端的当前风况。二者的时间身份必须等于
`sample.history_end`，而预测仍只由`x_window`经适配器生成，绝不读取`y_uv_raw`。该接口
只解决数据来源的一致性，尚未把风况观测转换为平台坐标载荷，也不接入任何控制策略。

`source_bound_forecast_and_current_enu_wind()`在同一来源约束下，将当前观测按既有
气象来向到ENU下风向的约定转换为只读二维风矢量。它仍是预测原点的实测风，不能替代
任一未来预测点，也不代表经过高度、艏向或转子相对风修正后的入流。

`assemble_replay_first_interval_physical_cycle_input()`仅将这对同源记录接入既有单周期
物理事实入口。它固定当前风来源标签，并继续要求平台初态与水泵状态的时间标签由调用方
显式提供，不将预测原点静默写入这些状态。重放样本缺失时直接返回`None`，不回退至未来
标签、外部当前风或持久性风况。

## P6.5 真实LSTM单记录链路检查

`scripts/validation/run_real_lstm_physical_cycle_smoke.py`以一条测试集重放记录检查真实
`ForecastModelAdapter`输出能否经`ReplayForecastEvidenceSource`进入首预测区间的物理事实链。
脚本只调用重放源一次，报告中的预测原点、模型身份和风矢量均从已组装的物理载荷记录读取。
每个当前或未来风矢量先按同一转子几何、风速高度处理和冻结运动学计算法向相对来流，再由冻结公开包中的ROSCO设定和性能表解析额定风速以下名义运行点。脚本会核对该法向相对来流与最终转子载荷路径使用的相对风投影完全一致。零剪切、`frozen_zero`平台运动、原点及预测区间均显式为零的波浪/其他载荷和零阻尼仍作为显式夹具输出，同时记录三舱初值、泵能力、请求目标、实际终态和剩余目标差。

该检查只验证数据和状态可以贯通，并不验证真实风机运行状态、平台响应、生命周期优劣或
控制性能。预测标签仍会随重放样本载入内存，但现有标签扰动测试确认它们不参与这条因果路径。

该脚本当前显式采用固定平台艏向、固定机舱相对偏航和正法向来流夹具，只适用于与该
夹具相容的风况记录，不构成全风向转子载荷验证。后续若要测试不同来流方向，必须提供
同一平台坐标系中的外部原点转子朝向状态，并在预测域内冻结使用，不可由预测风向自动反推。

## P6.6 来源绑定的额定风速以下名义运行点

`fowt_platform.rotor_operating_schedule`从冻结公开包中的UMaine Semi ROSCO配置读取
`v_min`、`v_rated`、`TSR_operational`、最低及额定转速和最小桨距，并与同一压缩包中的
二维\(C_T(\beta,\lambda)\)表共同使用。对于调用方已经明确声明为
`nominal_below_rated_generating`的记录，模块以法向相对入流计算转速，受最低和额定转速限制后
重新计算实际尖速比，再在性能表内插值。输出保留入流、桨距、转速、尖速比、\(C_T\)及两份来源哈希。

该模块不根据风速、预测事件或风向自行判断机组是否发电，不实现ROSCO动态、启停、偏航、顺桨或额定以上控制。入流处于或低于切入边界、处于或高于额定边界、反向或零来流、性能表外尖速比、负\(C_T\)或来源压缩包不一致时均直接拒绝，不钳制尖速比到表边界，也不回退为固定\(C_T\)。因此，它只为当前低阶物理链提供可追溯的额定以下准静态查表节点，不能被表述为真实机组运行状态重建。
