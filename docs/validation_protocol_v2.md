# 分阶段六小时验证协议 v2

## 适用范围

该协议用于预测辅助主动压载控制器的开发验证。每个工况固定持续6小时，单次实验最多30组。1组和3组仅用于程序诊断，正式的效果筛选按10组、20组和30组推进，不设置50组或150组自动运行阶段。

已投稿版本得到的19.85%累计泵量降幅仅作为旧版结果记录。旧程序的实现完整性有限，新版结果可能低于或高于该数值，均需由当前程序和验证数据重新确定。19.85%不得写入新版阶段门，也不作为回归目标、调参目标或继续研究的最低要求。

## 三层判断

每个阶段分别给出三类结果，不能用较大的泵量降幅掩盖程序或姿态问题。

| 判断层 | 主要内容 | 处理方式 |
|---|---|---|
| 程序完整性 | 三种算法物理配置一致、工况不重叠、规划预演与实际目标和泵量一致、参数冻结记录完整 | 任一硬错误均停止推进 |
| 安全性 | 不同姿态阈值的持续时间、是否新增大姿态工况、纵横摇RMS和p95变化 | 任一硬错误均停止推进 |
| 效果幅度 | 相对姿态反馈和无未来预测对照的泵量变化、改善工况数、置信区间和各类工况结果 | 独立判断，不替代前两层 |

泵量降幅超过30%时生成审计提示，重点复核目标生命周期、死区释放、预演与执行一致性以及姿态代价。该提示不是收益上限。复核未发现程序或姿态问题时，较高降幅可以作为正常结果保留。

## 阶段含义

| 阶段 | 用途 | 结果处理 |
|---:|---|---|
| 1组 | 复现程序问题，检查决策链、姿态门和预演执行一致性 | 仅作机制诊断，不评价算法效果，不据此选择参数 |
| 3组 | 检查同一修改在少量不同工况中是否触发异常 | 仍属程序诊断，不据此判断总体方向 |
| 10组 | 在风况增强、回落或反转、持续振荡和低扰动工况中进行最低规模的方向筛选 | 报告两种对照、改善工况数、离散性及姿态代价，不设固定百分比目标 |
| 20组 | 使用未参与上一阶段调节的工况复核结果是否依赖少数样本 | 结合均值、中位数、分布和异常工况人工判断，不以旧版19.85%作为通过条件 |
| 30组 | 在冻结参数后形成阶段性验证证据 | 报告置信区间和分类结果；置信区间用于判断方向是否稳定，不规定收益幅度 |

30组阶段只输出`supports_expanded_validation`。该字段只表示冻结参数下是否形成方向稳定的阶段性证据，不代表达到既定收益目标。即使该值为真，程序也不会自动建立或运行更大的实验，后续验证范围需另行决定。

## 必要清单

新协议在`staged_validation`中必须包含：

- 与`expected_cases`逐一对应的`case_intervals`，每段必须为21600秒且相互不重叠。
- `posture_feedback`、`no_future_prediction`和`prediction_assisted`三种算法的物理配置。平台、初始状态、水泵、舱容、控制步长和工况输入必须一致。
- 30组阶段的`parameter_manifest`，包括参数集标识、64位配置哈希、冻结阶段和曾用于开发的阶段。冻结时点之后不得再出现调参记录，30组结果也不得重新用于调参。

旧格式协议仍可读取。超过30组的旧协议可用于读取历史记录，但`runner_argv()`会拒绝启动。只有声明`staged_validation`的新协议才执行完整的六小时、区间、物理配置和参数冻结检查。

## 结果接口

`evaluate_validation_stage()`返回`StageEvaluation`：

- `integrity_passed`：程序完整性是否通过。
- `safety_passed`：安全性是否通过。
- `performance_passed`：效果幅度是否通过。1组阶段为`None`。
- `passed`：已评价层均通过。
- `evidence_level`：当前阶段证据级别。
- `supports_expanded_validation`：仅30组阶段返回布尔值，其余阶段为`None`。

1组和3组只回答程序是否按预期运行。涉及算法方向和参数取舍时，最低使用10组且不得按节泵结果挑选工况。参数修改后重新进行10组筛选，20组和30组结果不得回流用于调参，也不能直接复用此前阶段的结论。

## 固定工况清单

科研版V2的结果盲选工况保存在`configs/validation_cases_v2`：

- `stage10_cases.csv`：10组参数方向筛选工况。
- `stage20_cases.csv`：20组独立复核工况，不得用于调整参数。
- `stage30_cases.csv`：30组冻结验证工况，仅在参数冻结后运行。
- `selection_manifest.json`：保存分类阈值、固定抽样种子、源数据哈希、类别数量和时间重叠审计。

三层工况均来自预测模型测试集，只使用控制仿真前可获得的风况记录进行分类和抽样。累计泵量、姿态响应、水泵运行时间及候选动作结果均不参与选样。三层之间不存在时间重叠，且已排除与旧版170组工况及现有烟雾测试工况重叠的时段。清单生成方法见`scripts/analysis/build_v2_staged_case_sets.py`。
