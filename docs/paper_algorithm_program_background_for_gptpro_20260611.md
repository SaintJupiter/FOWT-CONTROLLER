## 1. 给 GPTPro 的一段项目背景

本项目研究短时风况预测如何接入浮式风机主动压载控制链路。预测模型不是水泵控制器，
不直接输出水泵开停、泵流量或最终舱水量命令。它输出未来风矢量、分段风险、事件概率
和压力代理信号；这些信号进入上层决策接口，用于识别未来风险、选择动作模式、管理压载
目标的保持/释放/拒绝/限幅/回退，并与原闭环反馈控制器、水泵执行约束和安全保护逻辑
共同形成实际动作。

最贴合程序的算法画像：

```text
短时风况预测
-> 0-20 / 20-40 / 40-60 min 三段风险与压力代理
-> 当前姿态与舱水量状态融合
-> 有限候选动作序列评价
-> 第一段动作进入目标生命周期管理
-> 生成或保持/释放/限幅目标舱水量
-> 原闭环反馈控制器 + 水泵执行约束
-> 平台姿态、泵量和目标状态反馈
```

正文不要把它写成：

- 预测模型直接控制水泵；
- 独立替换原闭环反馈控制器；
- 严格 MPC / QP / 连续变量在线优化；
- 完整气动载荷或平台力矩预测；
- 长期部署级生产控制器认证。

## 4. 风况预测输出

程序中 `ForecastModelAdapter` 的输出可概括为：

```math
(\hat{Y}_t,\hat{p}_t)=f_\Theta(X_t)
```

其中：

```math
X_t=\{x_{t-L+1},x_{t-L+2},\ldots,x_t\}
```

为历史风况特征窗口，`\hat{Y}_t` 为未来风矢量序列：

```math
\hat{Y}_t=\{(\hat u_{t+j},\hat v_{t+j})\}_{j=1}^{F}
```

`\hat{p}_t` 为事件概率或风险标志。正文中建议写“未来风矢量”，不要只写未来风速，
因为风向角在 0/360 度处存在跳变，程序采用 `u/v` 风矢量更稳定。

风矢量与风速/风向关系可写为：

```math
\hat V_{t+j}=\sqrt{\hat u_{t+j}^{2}+\hat v_{t+j}^{2}}
```

```math
\hat \alpha_{t+j}=
\operatorname{atan2}(-\hat u_{t+j},-\hat v_{t+j})
```

注意：上式只说明预测输出表达，不表示预测模型直接输出控制命令。

## 5. 三段风险窗口

程序中的控制链路按三个 20 min block 处理未来 60 min：

```text
block1: 0-20 min
block2: 20-40 min
block3: 40-60 min
```

可写成：

```math
B_1=\{1,2\},\quad B_2=\{3,4\},\quad B_3=\{5,6\}
```

每个 block 可以计算或接收以下风险信息：

- 风速爬升；
- 风向转变；
- 风矢量突变；
- 持续高风速；
- future relief；
- signflip；
- gusty oscillation；
- residual high；
- lowrisk；
- boundary warning。

论文中可以把风险状态概括为：

```math
R_{k,t}=\mathcal{R}(\hat{Y}_{t,j\in B_k},\hat{p}_{t,k}),\quad k=1,2,3
```

这里 `\mathcal{R}` 表示风险识别规则或事件概率阈值组合，不要写成黑箱分类神话。

## 6. 压力代理：控制接口变量，不是真实载荷

程序中 `pressure_proxy_vec()` 将未来风矢量转换为 pitch/roll 相关的二维压力代理。
它不是完整气动力，也不是平台真实力矩，只是让未来风况可以进入主动压载上层决策的
控制接口变量。

对第 `k` 个窗口，先计算均值风矢量：

```math
\bar u_k=\frac{1}{|B_k|}\sum_{j\in B_k}\hat u_{t+j},\quad
\bar v_k=\frac{1}{|B_k|}\sum_{j\in B_k}\hat v_{t+j}
```

```math
\bar V_k=\frac{1}{|B_k|}\sum_{j\in B_k}
\sqrt{\hat u_{t+j}^{2}+\hat v_{t+j}^{2}}
```

```math
\bar\alpha_k=\operatorname{atan2}(-\bar u_k,-\bar v_k)
```

风压幅值用风速平方归一化并截断：

```math
\rho_k=
\operatorname{clip}\left[
\left(\frac{\bar V_k}{V_{\mathrm{ref}}}\right)^2,
0,\rho_{\max}
\right]
```

二维压力代理可写成：

```math
q_k
=s_q
\begin{bmatrix}
-d_\theta \rho_k \cos\bar\alpha_k\\
d_\phi \rho_k \sin\bar\alpha_k
\end{bmatrix}
```

其中：

- `d_\theta`、`d_\phi` 为 pitch/roll 死区尺度；
- `V_ref` 程序默认约为 `12 m/s`；
- `rho_max` 程序默认约为 `1.5`；
- `s_q` 是符号约定系数。

正文解释建议：

> 压力代理用于把未来风速和风向趋势转换为与 pitch/roll 调节相关的二维上层决策变量，
> 不代表真实气动载荷或完整平台力矩。

## 7. 当前姿态融合

程序不是只看未来风，还把当前平台姿态纳入上层动作评价。当前姿态向量可写为：

```math
\theta_t=[\theta_{\mathrm{pitch},t},\theta_{\mathrm{roll},t}]^T
```

姿态状态项可概括为：

```math
r_t
=g_\theta d\odot
\operatorname{clip}
\left(
\theta_t\oslash d,
-r_{\max},r_{\max}
\right)
```

其中：

- `d=[d_\theta,d_\phi]^T` 为 pitch/roll 死区尺度；
- `g_theta` 程序默认约为 `0.40`；
- `r_max` 程序默认约为 `6.0`；
- `\odot` 与 `\oslash` 表示逐元素乘除。

进入三个未来窗口时，当前姿态影响可随窗口衰减：

```math
z_k=q_k+\lambda^{k-1}r_t
```

其中 `lambda` 程序默认约为 `0.85`。论文可解释为：上层调节同时考虑未来风况压力和
当前平台已经存在的姿态偏差。

注意：安全检查可使用未衰减或未弱化的姿态视图，因此不能写成所有安全判断都使用
弱化后的 `z_k`。

## 8. 有限候选动作集合

程序中的基础动作集合为：

```text
hold
pump_saving
active_small
active_medium
active_reverse_small
```

正文建议映射为：

| 程序动作 | 中文表述 | 含义 |
|---|---|---|
| `hold` | 保持 | 不主动生成新的压载补偿 |
| `pump_saving` | 省泵小动作 | 低强度、偏经济性的补偿 |
| `active_small` | 主动小动作 | 常规主动补偿 |
| `active_medium` | 主动中等动作 | 风险或姿态需求较高时的较强补偿 |
| `active_reverse_small` | 小幅反向动作 | 方向反转或过补偿后的小幅反向释放 |

程序按三个 20 min block 构造三步动作序列：

```math
\mathbf a=(a_1,a_2,a_3),\quad a_k\in\mathcal A
```

因为 `|\mathcal A|=5`，候选序列数量是：

```math
5^3=125
```

这点很重要：论文可以写“有限候选动作序列评价”，不要写“连续变量严格在线优化”。

## 9. 动作向量与目标质量变化

程序先把动作映射到 pitch/roll 补偿向量。论文可概括为：

```math
c_k=\eta(a_k)\,
d\,
\frac{\mathcal D(z_k)}
{\|\mathcal D(z_k)\|_2+\varepsilon}
```

其中：

- `\mathcal D(\cdot)` 是逐轴死区函数；
- `\eta(a_k)` 是动作强度；
- `hold` 对应 `0`；
- `pump_saving`、`active_small`、`active_medium`、`active_reverse_small`
  对应不同强度或反向方向。

强度关系可写成“由小到大”，不必在正文暴露所有内部数值。若需要说明，可写：

```text
pump_saving < active_small < active_medium
```

动作向量通过三舱分配矩阵转换为目标质量变化。程序中的补偿分配可概括为：

```math
\Delta m_t
=
m_q M_c(c_1\oslash d)
```

其中 `m_q` 是单步动作质量尺度，程序默认约为 `1.8e5 kg`。`M_c` 可写为三舱补偿
分配矩阵；若不想暴露过多内部实现，正文可以只说明“三舱分配矩阵将 pitch/roll
补偿向量转换为各舱目标质量变化”。

目标舱水量限幅：

```math
m_t^*=
\operatorname{clip}(m_t+\Delta m_t,\ 0,\ m_{\max})
```

其中 `m_max` 程序默认约为：

```math
m_{\max}=1850\times1025\ \mathrm{kg}
```

## 10. 候选序列评价：可以写评分，不能写成严格优化器

程序中 `evaluate_sequence()` 对 125 个候选序列进行评价，包含：

- 姿态残差代价；
- 终端残差代价；
- 泵送工作量代理；
- 泵送持续代价；
- 启停代价；
- 方向切换代价；
- 反向动作惩罚；
- 舱容饱和惩罚；
- 姿态包络软惩罚；
- 安全硬拒绝。

论文推荐写成有限候选评分：

```math
S(\mathbf a)=
w_p C_{\mathrm{pump}}
+w_d C_{\mathrm{duration}}
+w_s C_{\mathrm{start}}
+w_c C_{\mathrm{switch}}
+w_r C_{\mathrm{reverse}}
+w_a C_{\mathrm{att}}
+w_T C_{\mathrm{terminal}}
+w_e C_{\mathrm{envelope}}
+C_{\mathrm{hard}}
```

选择：

```math
\mathbf a^*
=
\arg\min_{\mathbf a\in\mathcal A^3_{\mathrm{feasible}}}
S(\mathbf a)
```

必须配套说明：

> 上式是对有限候选动作序列评价过程的论文概括，不表示本文实现了连续变量在线优化、
> 二次规划或严格 MPC 求解。实际控制只采用第一段动作，并在下一个 10 min 更新周期
> 重新评价。

如果导师不喜欢“优化”字眼，可改成：

```math
\mathbf a^*=\operatorname{select}
\left(\{\mathbf a_i,S_i\}_{i=1}^{125}\right)
```

## 11. 硬约束与门控逻辑

程序中有多个硬拒绝或放行门：

- 舱容接近上/下限时，禁止继续向相同方向推进；
- 水泵已满速且仍要求动作时，可拒绝候选动作；
- 当前姿态接近安全边界时，禁止第一步选择过弱动作；
- 未来预测残差越过安全边界时，拒绝候选序列；
- 中等动作必须相对小动作有明显必要性；
- 小幅反向动作必须满足未来反向或过补偿条件；
- 预测缺失或不可信时，走保守回退。

论文可用门控函数概括：

```math
g_i(\mathbf a,z_t,R_{1:3,t})\in\{0,1\}
```

候选集合：

```math
\mathcal A^3_{\mathrm{feasible}}
=
\{\mathbf a\in\mathcal A^3\mid g_i(\mathbf a,z_t,R_{1:3,t})=1,\ \forall i\}
```

这比写“严格安全约束优化”更忠实。

## 12. 目标生命周期管理

上层决策不是每个时刻都简单刷新目标。程序通过 `target_lifecycle.py` 维护目标舱水量状态，
包括：

- 从当前质量和动作增量生成新目标；
- 将目标设为当前质量；
- 暂停目标后恢复；
- 限制目标距离当前质量的最大偏差；
- 标记目标复用、刷新、恢复；
- 记录目标年龄、目标误差和目标变化量。

论文可写成：

```math
m_t^*
=
\mathcal T(m_{t-1}^*,m_{fb,t},c_1,z_t,\xi_t)
```

其中：

- `m_{t-1}^*` 为上一周期目标；
- `m_{fb,t}` 为原闭环反馈目标；
- `c_1` 为选中序列的第一段动作向量；
- `z_t` 为姿态与风况融合状态；
- `\xi_t` 为目标年龄、泵状态、回退标志、边界标志等生命周期状态。

`\mathcal T` 的输出可能是：

- 保持旧目标；
- 刷新新目标；
- 释放到当前质量；
- 限幅目标；
- 拒绝本次目标更新；
- 回退原闭环反馈目标。

这部分是论文创新表达重点，不能被简化成“调权重”。

## 13. 水泵执行约束

上层只给目标或目标变化，不直接给最终泵命令。执行层还要经过水泵和舱容约束：

```math
\dot m_{i,t}^{cmd}
=
\operatorname{sat}
\left(
\frac{m_{i,t}^{*}-m_{i,t}}{\Delta t},
-\dot m_i^{\max},
\dot m_i^{\max}
\right)
```

```math
m_{i,t+\Delta t}=m_{i,t}+\dot m_{i,t}^{cmd}\Delta t
```

实际执行还受：

- 舱容上/下限；
- 水泵最大流量；
- 泵速爬升/下降；
- 停泵/重启滞回；
- 最小开停时间；
- 近目标保持；
- 安全回退。

正文必须反复保持这个边界：预测辅助调节层不绕过执行层。

## 14. 安全边界与回退

安全相关逻辑可概括为三类：

1. 当前姿态边界：如果当前 pitch/roll 已接近边界，弱动作或保持动作会被限制。
2. 预测姿态边界：如果候选序列导致未来残差越过安全阈值，序列被拒绝。
3. 反应式回退：预测缺失、不可信、目标停滞或姿态恶化时，回到原闭环反馈/安全动作。

姿态指标建议写：

```math
\psi(t)=\max(|pitch(t)|,|roll(t)|)
```

阈值暴露时间：

```math
T_{\psi>\gamma}
=
\int_{t_0}^{t_0+T}
\mathbf 1\{\psi(t)>\gamma\}\,dt,
\quad
\gamma\in\{5^\circ,7.5^\circ,10^\circ\}
```

阈值语义：

- `5 deg`：service-pressure band，不是 hard failure；
- `7.5 deg`：较大姿态压力；
- `10 deg`：严重运行边界尾部。
