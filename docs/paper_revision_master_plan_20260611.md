### 1.2 导师术语硬约束

该层的真实作用保持不变：工况识别、目标保持/释放、动作限幅、边界拒绝、

避免读者误解为机器学习中的有标签训练范式。

- 预测驱动水泵动作

### 1.5 真正需要修改的关键细节

后续改稿的重点不是章节标题，而是把算法写成可读、可复核、与程序一致的数学化控制链路。
第 1 章必须优先补强以下六类内容。

1. 数据流必须闭合

正文和图 1 都要形成完整数据流：

```text
历史风况窗口 X_t
-> 未来风矢量与事件概率 (\hat Y_t,\hat p_t)
-> 三段风险 R_{1:3,t} 与压力代理 q_{1:3,t}
-> 当前姿态、舱水量、水泵状态、目标生命周期状态
-> 融合状态 \chi_t
-> 有限候选动作序列评价与门控拒绝
-> 第一段动作或决策状态 s_t
-> 目标生命周期管理 m_t^*
-> 水泵执行约束 \dot m_{i,t}^{cmd}
-> 平台姿态、泵量和目标状态反馈
```

每一段都要说明输入、输出和进入下一模块的条件。不能只写“预测结果用于提前调节”。

2. 数学语言必须服务模块职责

公式要按模块出现，不要堆公式。每个公式后至少交代：

- 变量维度或物理含义；
- 该量来自预测、反馈还是生命周期状态；
- 该量进入哪个后续模块；
- 该公式是接口抽象、工程评分还是执行约束。

压力代理、风险窗口、评分函数、目标生命周期和水泵饱和约束必须分清层级。尤其要说明：
压力代理不是气动力模型，评分函数不是连续在线优化器，执行约束不是预测模型直接给泵命令。

3. 姿态与预测信息融合必须给出核心公式和依据

当前姿态向量建议写为：

```math
\theta_t=[\theta_{\mathrm{pitch},t},\theta_{\mathrm{roll},t}]^T
```

将当前姿态归一到 pitch/roll 死区尺度：

```math
r_t
=g_\theta d\odot
\operatorname{clip}
\left(
\theta_t\oslash d,
-r_{\max},r_{\max}
\right)
```

其中 `d=[d_\theta,d_\phi]^T` 为 pitch/roll 死区尺度，`g_\theta` 为当前姿态反馈权重，
`r_max` 限制当前姿态项过度放大。预测压力代理与当前姿态融合为：

```math
z_k=q_k+\lambda^{k-1}r_t,\quad k=1,2,3
```

写作依据：

- `q_k` 表示未来第 `k` 个 20 min 风况窗口对 pitch/roll 调节方向的预览提示；
- `r_t` 表示当前平台已经存在的姿态偏差；
- `\lambda^{k-1}` 表示当前姿态对更远预测窗口的影响逐步衰减；
- 安全判别仍应保留未弱化的当前姿态视图，不能只依赖衰减后的融合量。

这组公式是算法章的核心，不应只在结果分析中用文字带过。

4. 策略判别原理必须写成门控加有限候选评价

策略判别不要写成“经验规则若干条”，也不要写成不存在的严格优化器。推荐写成：

```math
g_i(\mathbf a,z_t,R_{1:3,t})\in\{0,1\}
```

```math
\mathcal A_{\mathrm{feasible}}^3
=
\{\mathbf a\in\mathcal A^3\mid g_i(\mathbf a,z_t,R_{1:3,t})=1,\ \forall i\}
```

再用有限候选评分选择动作：

```math
\mathbf a^*=\operatorname{select}
\left(\{\mathbf a_j,S_j\}_{j=1}^{125}\right)
```

正文必须配判别表，至少覆盖：

- 预测缺失或不可信：回到保守反馈；
- 当前姿态接近安全边界：拒绝过弱动作；
- future relief：倾向保持或释放目标，避免追踪即将失效的补偿；
- signflip / boundary：倾向拒绝或小幅反向，避免方向误判；
- lowrisk：保持或省泵动作；
- residual high / sustained high：允许更强补偿，但仍受舱容和泵约束限制。

5. 参数设定依据必须分类说明

参数不要只列数值。建议把参数来源分成四类：

| 参数类型 | 示例 | 正文依据写法 |
|---|---|---|
| 物理/执行约束 | 舱容、最大泵流量、最小开停时间 | 来自主动压载执行系统与仿真平台约束 |
| 时间尺度参数 | 10 min 更新、60 min horizon、三个 20 min block | 来自风况数据分辨率、预测有效时域和控制更新节奏 |
| 姿态与安全尺度 | pitch/roll 死区、`5/7.5/10 deg` 阈值 | 来自服务压力带、较大姿态压力和严重尾部暴露定义 |
| 评分/动作强度参数 | `g_theta`、`\lambda`、动作强度、评分权重 | 来自冻结 profile、参数敏感性筛选或工程折中，且 paired comparison 中保持固定 |

如果某个参数目前没有充分标定证据，不要硬说“最优”。应写成“在冻结配置中采用”，并在
结果章说明其角色。

6. 结果章只验证算法链路，不替代算法说明

第 3 章可以用预测曲线、风险窗口和代表 episode 解释动作差异，但不能把这些解释当成
算法定义。算法定义必须在第 1 章完成；第 3 章只回答“这些算法环节在 paired casebook
中产生了什么结果，以及哪些工况中更容易/不容易产生收益”。

## 2. 论文核心定位

推荐主定位：

> 本文提出一种短时风况预测辅助的浮式风机主动压载上层协调调节算法。
> 预测模块基于历史风况输出未来风矢量、分段风险窗口、风况事件标志和
> 压力代理信号；这些信息不直接生成水泵命令，而是进入上层决策接口，
> 用于识别预测可行动工况、边界工况和低机会工况，并管理压载目标的保持、
> 释放、限幅、拒绝和安全回退。原闭环反馈控制器、水泵执行约束和安全保护
> 逻辑仍作为执行层保留。本文验证目标限定为冻结 6 h episode-level paired
> casebook 中的泵耗与姿态暴露比较，并用 12 h mixed-regime 结果披露收益
> 稀释和服务压力带折中。

最简方法画像：

```text
有限上层决策状态机
+ 预测风险门控
+ 目标生命周期管理
+ 水泵执行约束
+ paired casebook 验证
```

不要把论文写成：

- 风况预测模型精度竞赛；
- 预测模型直接驱动水泵的控制器；
- 长期部署级生产控制器认证；
- 普通约束优化方法；
- 历史分支结果的大拼盘。

## 3. 题名和摘要定位

### 3.1 推荐题名

首选：

```text
短时风况预测辅助的浮式风机主动压载上层协调调节算法
```

英文可写为：

```text
Short-Horizon Wind-Condition Prediction-Assisted Upper-Layer Coordinated Regulation
Algorithm for Active Ballast Systems of Floating Offshore Wind Turbines
```

备选：

```text
基于短时风况预测与风险识别的浮式风机主动压载协调调节方法
```

不推荐：

```text
短时风况预测驱动的浮式风机主动压载协调调节方法
短时风况预测辅助的浮式风机主动压载约束调节方法
```

前者“驱动”偏强，容易暗示预测直接驱动执行；后者“约束调节”偏窄，不能
覆盖决策状态和目标生命周期贡献。

### 3.2 摘要必须包含

- 问题：主动压载主要依赖当前姿态反馈，对短时未来风况预判利用不足。
- 方法：短时风况预测输出未来风矢量、风险窗口、事件标志和压力代理。
- 架构边界：预测不直接输出水泵命令；原闭环反馈控制器和安全执行层保留。
- 验证：冻结 casebook 下的 paired comparison。
- 主结果：只使用当前冻结的 production-near headline 结果。
- 支撑结果：positive-only、historical/specialist 分支必须降级并标注角色。
- 边界：12 h 是 robustness disclosure；24 h 是 future work。

摘要推荐六句式：

1. 应用场景和不足：浮式风机主动压载依赖当前反馈，对短时未来风况利用不足。
2. 提出算法：提出短时风况预测辅助的主动压载上层协调调节算法。
3. 方法组成：预测未来风矢量，构造分段风险窗口、事件标志和压力代理。
4. 链路边界：预测信息进入上层决策接口，不直接生成水泵命令，原闭环反馈和执行
   安全逻辑保留。
5. 冻结证据：只报告当前 6 h production-near paired headline。
6. 结论边界：说明短时窗口内减少部分不必要泵送，严重姿态暴露不增加或有界，
   不外推到长期部署。

可作为摘要草稿的骨架：

> 针对浮式风机主动压载主要依赖当前姿态反馈、对短时未来风况变化利用不足的问题，
> 提出一种短时风况预测辅助的主动压载上层协调调节算法。该算法以历史风况窗口为
> 输入，预测未来 60 min 风矢量，并构造 0-20、20-40 和 40-60 min 三段风险窗口、
> 风况事件标志及压力代理信号。上述信息用于上层决策接口中的工况识别、目标保持/
> 释放、动作限幅与安全回退，而不直接生成水泵命令；原闭环反馈控制器、水泵执行
> 约束和安全保护逻辑保持不变。在冻结的 6 h episode-level paired casebook 中，
> 预测辅助上层协调调节策略相对无预测闭环反馈策略累计泵量降低 6.01%，`t>5 deg`
> 减少 64 s、`t>7.5 deg` 减少 44 s、`t>10 deg` 不增加。结果表明，短时风况预测
> 可在短时冻结工况窗口中减少部分不必要泵送，并保持严重姿态暴露指标有界。

### 3.3 摘要禁止写法

- 长期稳定节泵；
- 全工况普遍有效；
- 部署级验证完成；
- 20 年闭环控制验证；
- 姿态响应全面改善；
- 预测模型直接控制水泵；
- 只报节泵不报姿态代价。

### 1.3 决策状态、风险门控与有限候选动作评价

推荐状态表达：

```math
\chi_t = \{R_{1:3,t}, q_{1:3,t}, z_t, h_t\}
```

其中：

- `R_{1:3,t}`：0-20、20-40、40-60 min 分段风险；
- `q_{1:3,t}`：分段压力代理；
- `z_t`：当前 pitch/roll、压载水量、水泵状态等反馈状态；
- `h_t`：目标生命周期状态，如 hold、latch、release、fallback。

决策状态：

```math
s_t = \mathcal{G}(\chi_t)
```

```math
s_t \in \{\text{hold},\text{release},\text{safe},\text{cap},\text{veto},\text{fallback}\}
```

推荐门控文字：

```text
预测缺失或反馈异常 -> fallback
边界拒绝条件触发 -> veto
危险预警或姿态尾部风险触发 -> safe
预测可行动且姿态余量满足 -> release
低风险或低机会窗口 -> hold
存在不确定风险但不宜完全释放 -> cap
```

如果需要写评分函数，只写有限候选状态评分：

```math
S_j =
w_p C_{\mathrm{pump},j}
+ w_r C_{\mathrm{risk},j}
+ w_s C_{\mathrm{switch},j}
+ w_b C_{\mathrm{barrier},j},
\quad
j\in\mathcal S_{\mathrm{cand}}
```

```math
s_t=\arg\min_{j\in\mathcal S_{\mathrm{cand}}}S_j
```

必须配套说明：

> 上式仅用于概括有限上层决策状态之间的工程评分选择，不表示本文实现了连续变量在线优化或严格约束规划求解。

### 1.4 目标生命周期管理与水泵执行约束

推荐表达：

```math
m_t^* = \mathcal{T}(m_{t-1}^*, m_{fb,t}, s_t, z_t)
```

其中 `m_{fb,t}` 是原闭环反馈目标，`\mathcal{T}` 表示：

- 保持当前目标；
- 释放目标；
- 更新目标；
- 拒绝目标更新；
- 回退原闭环反馈目标。

写作重点：预测辅助调节层的贡献不只是调权重，而是管理目标生命周期，避免在
future relief、signflip boundary 或 lowrisk 背景中追踪即将失效或低价值的目标。

推荐动作限幅表达：

```math
\Delta m_t^{cmd}
=
\operatorname{clip}
\left(
m_t^*-m_t,
-B(s_t),B(s_t)
\right)
```

水泵执行约束：

```math
\dot m_{i,t}^{cmd}
=
\operatorname{sat}
\left(
\frac{\Delta m_{i,t}^{cmd}}{\Delta t},
-\dot m_i^{\max},\dot m_i^{\max}
\right)
```

并说明受以下约束：

- 舱容限制；
- 水泵最大流量；
- 泵速爬升/下降；
- 停泵/重启滞回；
- 最小开停时间；
- 近目标保持；
- fallback。

## 7. 外部 GPT / 评审必须补充的背景

给任何外部 GPT、导师或评审修改建议前，必须先补充以下背景：

1. 预测模型不是直接控制器。
2. 预测模型不输出水泵开停命令或泵流量。
3. 原闭环反馈控制器保留。
4. 水泵执行层、安全层、fallback、pump limit、舱容限制和滞回保留。
5. 预测信息进入 preview provider / upper-layer decision interface。
6. 上层调节层包含工况识别、hold、release、veto、cap、safe、fallback。
7. 上层调节层还管理目标保持、释放、拒绝、刷新和回退。
8. FINO1 长期数据是风况数据基础，不是 20 年闭环控制验证。
9. 6 h 是 episode-level 主证据。
10. 12 h 是 robustness disclosure。
11. 24 h 是 future deployment-scale validation。
12. P2/C3/W1/PSC/deadband 不能并入 headline。
13. positive-only 是支撑证据，不是全工况结论。
14. 所有指标来自 raw 1 Hz，平滑只用于展示。
15. `5 deg` 是 service-pressure band，不是 hard failure。
16. `7.5 deg` 和 `10 deg` 是较大/严重尾部指标。
