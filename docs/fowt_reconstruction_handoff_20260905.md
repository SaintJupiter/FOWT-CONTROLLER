## 2. 研究背景与当前目标

研究对象为三舱半潜式浮式风机主动压载系统。三个压载舱分别与海水交换，通过改变舱内水量形成纵摇和横摇恢复力矩。水泵调节速度明显慢于风况变化，因此控制器需要在保证姿态响应处于低阶模型适用范围的前提下，利用短时风况预测决定当前是否继续、释放或调整压载目标。

短论文曾使用旧程序得到约19.85%的累计泵量差异，但旧代码存在预测来源、目标状态、候选动作和实际水泵执行关系不够清楚的问题。该历史结果只可视为旧实现的冻结快照，不能作为当前重构版本的性能证据，也不能作为调参目标。

本阶段目标不是追求某个节泵比例，而是把仓库收敛为一套研究级、可追踪的控制链，使每次结果能够回答：

1. 控制器实际读取了哪一份预测。
2. 预测风况如何转换为平台广义载荷。
3. 控制器比较了哪些可执行目标。
4. 最终为什么选择当前目标。
5. 水泵在本周期实际完成了多少调节。
6. 实际水量如何改变平台质量、恢复力矩和下一周期状态。

## 3. 当前系统的准确身份

当前活跃研究路径是一个面向慢速三舱压载调节的确定性线性预览MPC原型，主要包含：

- 真实LSTM风矢量预测及源记录绑定
- 当前平台运动下的相对来流计算
- 准静态转子载荷及平台六维广义载荷转换
- 静平衡点附近的小角度六自由度增量模型
- 两个零净质量差动压载模态
- 线性凸预览优化
- 继续已有目标、释放到当前水量和采用新MPC目标三类目标生命周期比较
- 首个控制块的真实水泵状态预演
- 只提交当前控制块，下一周期依据实际水量、泵状态和平台状态重新规划

当前系统不是非线性MPC、鲁棒MPC、随机MPC、完整变质量船舶模型，也不是经过全工况验证的工程控制器。未来预测时域内的平台运动仍采用冻结近似，5度只作为当前低阶横摇和纵摇模型的暂定使用范围。

## 4. 当前端到端链路

```text

  -> 一次LSTM推理并生成不可变源记录
  -> 基于当前实际平台状态计算相对来流
  -> 转换当前与未来转子广义载荷
  -> 组成MPC扰动块
  -> 组装本周期平台、水泵和未完成目标状态
  -> 求解自由MPC目标
  -> 比较继续、释放和新目标
  -> 以规划器可见载荷预演首个控制块
  -> 提交一个水泵请求
  -> 按真实泵状态、流量爬升、启停与舱容执行
```

## 5. 已冻结的关键原则

后续工作不得破坏以下原则：

1. 同一预测起点只进行一次LSTM推理。预检和执行必须消费同一份不可变记录。
2. 预测可靠度和事件概率可以影响是否采用预测或如何决策，但不得直接缩放物理风载荷。
3. 当前实测水量、未完成目标、新请求目标、泵可达水量和实际到达水量必须分别记录。
4. MPC可以预测完整时域，但每个周期只提交首个动作。
5. 候选目标必须从同一实际初始状态比较，不能让不同候选串行继承彼此的预演状态。
6. 各算法使用相同实测风况和初始状态。平台状态分化后，相对来流与实际转子载荷可以自然分化，不能强行规定各算法承受完全相同的广义载荷。
7. 姿态控制约束、数值终止上限和低阶模型适用范围是三个不同概念。
8. 5度只表示当前低阶横摇和纵摇模型的暂定保守使用范围，不是安全认证边界，也不表示5度以内动态响应已被完整验证。
9. 超出实际使用范围的周期只能保留为诊断，不得进入性能统计，也不得把越界末状态传给下一周期。
10. 单元测试只能证明接口和算法语义，不等同于物理准确性或控制性能验证。

恢复后先运行公共单周期与聚焦回归测试，确认`rollout_config`修复有效。随后决定姿态反馈基线采用模型相关PD还是传统PI/PI-D，只补齐这一基线并接入共用物理执行链。完成公平性与动作语义检查后，再修实验身份并运行极少量固定六小时工况。期间不得追逐节泵比例、混入旧控制逻辑或扩展新的治理框架。
